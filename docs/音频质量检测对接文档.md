# 音频质量检测对接文档

以下示例使用本地地址 `http://127.0.0.1:8090`。联调时替换为部署环境分配的服务地址。应用路由层未配置鉴权，网关的访问地址和鉴权方式以部署环境为准。运行中的服务可通过 `/docs` 查看 Swagger UI。

## 音频质检

`POST /audio/qc` 接收单个音频文件，并在本次 HTTP 请求中返回质检结果。请求类型为 `multipart/form-data`。

| 表单字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `audio_file` | 文件 | 是 | 上传实际音频文件，例如 WAV、MP3、AAC 或 M4A。能否处理取决于部署环境的 FFmpeg 能否解码。 |
| `task_id` | 字符串 | 否 | 传入非空值时原样用作响应中的 `request_id`。省略时生成 `文件名（不含扩展名）_8位随机字符`，后缀由小写字母和数字组成。 |

`task_id` 用于关联请求，每次提交都会执行质检。同一时刻提交的多个任务应使用不同的 ID，以便区分健康检查中的任务记录。服务自动将音频转换为 16 kHz 单声道后进行分析。

| 限制 | 仓库配置 | 对应配置项 |
| --- | --- | --- |
| 音频文件大小 | 最大 300 MiB（314,572,800 字节） | `audio_qc.max_file_size_mb` |
| 解码后音频时长 | 10 秒至 110 分钟，含上下限 | `audio_qc.min_duration_ms`、`audio_qc.max_duration_ms` |

线上限制以部署配置和网关设置为准。客户端超时需覆盖文件上传及处理时间，长音频和并发请求可能耗时更久。

仓库配置中的其他检测参数如下。通过 Docker 挂载外部配置文件时，以实际挂载的配置为准。

| 配置项 | 仓库配置值 | 说明 |
| --- | --- | --- |
| `audio_qc.return_segments` | `true` | 是否返回人声分段。 |
| `audio_qc.need_clarity` | `true` | 是否计算清晰度。 |
| `audio_qc.silence_dbfs` | `-50.0` | 静音检测阈值，单位为 dBFS。 |

### 请求示例

```bash
curl -sS http://127.0.0.1:8090/audio/qc \
  -F 'audio_file=@sample.wav' \
  -F 'task_id=qc-demo-001'
```

将 `sample.wav` 替换为符合大小和时长限制的本地音频。使用 HTTP 客户端构造 multipart 表单时，让客户端生成包含 boundary 的 `Content-Type`。

#### Python 示例

以下示例使用 `requests`。请根据部署环境的响应耗时调整超时设置。

```python
import requests

url = "http://127.0.0.1:8090/audio/qc"

with open("sample.wav", "rb") as audio:
    response = requests.post(
        url,
        files={"audio_file": ("sample.wav", audio, "audio/wav")},
        data={"task_id": "qc-demo-001"},
        timeout=300,
    )

if response.status_code != 200:
    raise RuntimeError(f"HTTP 请求失败（状态码 {response.status_code}）")

payload = response.json()
if payload["status_code"] != 200:
    raise RuntimeError(
        f"音频质检失败（业务码 {payload['status_code']}，"
        f"请求 ID {payload['request_id']}）"
    )

result = payload["data"]
print(result["has_speech"], result["speech_ratio"])
```

### 响应及成功判定

质检处理生成的业务响应使用 HTTP 200，客户端还需判断 JSON 中的 `status_code`。业务码为 `200` 时读取 `data`，其他业务码的 `data` 固定为 `{}`。客户端应单独处理网络超时和非 200 的 HTTP 响应。表单解析、参数校验和网关错误可能返回非 200，响应结构由对应组件决定。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `request_id` | 字符串 | 请求关联 ID。缺少文件字段或文件名时返回 `unknown`，上传有文件名但内容为 0 字节时仍返回该请求的 ID。 |
| `status_code` | 整数 | 业务状态码。 |
| `data` | 对象 | 成功时为质检结果，业务失败时为空对象。 |

成功响应示例

```json
{
  "request_id": "qc-demo-001",
  "status_code": 200,
  "data": {
    "is_silent": false,
    "has_speech": true,
    "speech_ratio": 0.356,
    "has_clip": true,
    "clip_detail": {
      "clip_count": 2,
      "times_ms": [500, 2300]
    },
    "clarity": 79.25,
    "clarity_detail": {
      "snr_db": 18.2,
      "hf_ratio": 0.021,
      "spectral_flatness": 0.12
    },
    "vad": {
      "segments_ms": [[120, 980], [1500, 4200]],
      "speech_ms": 3560
    }
  }
}
```

该示例对应一段 10 秒音频。分段起止时间和削波发生时间均以音频起点为零点，单位为毫秒。

| `data` 内字段 | 类型 | 说明 |
| --- | --- | --- |
| `is_silent` | 布尔值 | 是否达到服务配置的静音判定条件。 |
| `has_speech` | 布尔值 | 合并后的人声时长达到 300 毫秒时为 `true`。 |
| `speech_ratio` | 数值 | 合并后的人声时长除以音频总时长，限制在 `[0, 1]`，最多保留 4 位小数。 |
| `has_clip` | 布尔值 | 是否检测到至少一次削波事件。 |
| `clip_detail` | 对象或 `null` | 无削波时为 `null`。 |
| `clip_detail.clip_count` | 整数 | 削波事件数。 |
| `clip_detail.times_ms` | 整数数组 | 各次削波事件的起始时间，单位为毫秒。 |
| `clarity` | 数值或 `null` | 清晰度评分，范围 0 至 100。当 `need_clarity=false` 时为 `null`。 |
| `clarity_detail` | 对象或 `null` | 清晰度指标。当 `need_clarity=false` 时为 `null`。 |
| `clarity_detail.snr_db` | 数值 | 信噪比，单位为 dB。 |
| `clarity_detail.hf_ratio` | 数值 | 高频能量占比。 |
| `clarity_detail.spectral_flatness` | 数值 | 谱平坦度。 |
| `vad` | 对象 | 人声活动检测结果。 |
| `vad.segments_ms` | 整数对数组 | 按起始时间排序的合并分段，每段为 `[开始毫秒, 结束毫秒]`。当 `return_segments=false` 时为 `[]`。 |
| `vad.speech_ms` | 整数 | 合并分段的时长之和，单位为毫秒。关闭分段返回时仍会返回此值。 |

相邻人声片段的间隔小于或等于 `audio_qc.merge_gap_ms` 时会合并，间隔计入合并后的人声时长。仓库配置的合并间隔为 120 毫秒。

### 业务状态码

| 状态码 | 含义 |
| --- | --- |
| `200` | 质检成功。 |
| `1001` | 缺少音频文件、文件名为空或文件内容为空。 |
| `1002` | 解码后的音频时长超出配置范围。 |
| `1003` | 音频文件超过大小限制。 |
| `2001` | FFmpeg 解码或转换失败。 |
| `2002` | 转换后的音频采样率校验失败。 |
| `2003` | 转换后的音频读取失败或采样数据无效，例如无样本、NaN 或 Inf。 |
| `3001` | 人声活动检测（VAD）推理失败。 |

例如，文件时长超出范围时，HTTP 状态为 200，响应体如下。

```json
{
  "request_id": "qc-demo-001",
  "status_code": 1002,
  "data": {}
}
```

## 健康检查

`GET /audio/health` 无需请求参数，返回当前服务进程的运行信息和任务统计。成功时 HTTP 状态为 200。

```bash
curl -sS http://127.0.0.1:8090/audio/health
```

```json
{
  "status": "healthy",
  "version": "1.0.0",
  "start_time": "2026-11-27 10:00:00",
  "uptime_seconds": 3600,
  "uptime_formatted": "1h 0s",
  "total_requests": 5,
  "success_count": 3,
  "failed_count": 1,
  "processing_count": 1,
  "processing_ids": ["qc-demo-002"],
  "queued_count": 0,
  "queued_ids": []
}
```

- `status` 固定为 `healthy`，可用于确认 HTTP 服务可达。质检联调应通过上传音频验证处理链路。
- `version` 为配置中的服务版本，`start_time` 使用服务进程的本地时间，格式为 `YYYY-MM-DD HH:MM:SS`。
- `uptime_seconds` 为运行秒数，`uptime_formatted` 为格式化的运行时长。任务统计按进程记录，重启后重置。
- `total_requests` 统计进入任务处理流程的质检请求。缺少文件字段或文件名的请求会在计数前返回。
- `success_count` 和 `failed_count` 分别为已记录的质检成功和失败次数。
- `processing_count` 为当前处理中记录的数量，`processing_ids` 为当前处理中的请求 ID 列表，按字母顺序排序。当前实现将等待 VAD 的请求计为处理中，`queued_count` 和 `queued_ids` 分别返回 `0` 和 `[]`。
