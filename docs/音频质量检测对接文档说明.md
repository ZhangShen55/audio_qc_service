# 音频质检服务接口对接文档

## 1. 接口概览

音频质检服务用于检测上传音频中的静音、人声、削波和清晰度等指标。

服务当前提供以下接口：

| 接口 | 方法 | 说明 |
|---|---|---|
| `/audio/health` | `GET` | 查询服务健康状态和运行统计 |
| `/audio/qc` | `POST` | 上传音频并执行质检 |

当前服务没有鉴权逻辑。鉴权、限流和 HTTPS 建议由网关或反向代理统一处理。

## 2. 基本约定

- 默认服务地址：`http://127.0.0.1:8090`
- 请求编码：音频质检使用 `multipart/form-data`
- 服务端 HTTP 状态码：正常处理时固定返回 `200`
- 业务处理结果：通过响应 JSON 的 `status_code` 判断
- `status_code == 200` 表示质检成功；其他值表示失败
- 失败时 `data` 固定为空对象 `{}`
- 音频会先由 FFmpeg 解码并重采样为单声道、16 kHz WAV，再进行后续检测

> 注意：当前实际路由是 `/audio/qc`，不是 `/v1/audio/qc`；上传字段是 `audio_file`，不是 `file`。

## 3. 健康检查

### 3.1 请求

```http
GET /audio/health
```

示例：

```bash
curl http://127.0.0.1:8090/audio/health
```

### 3.2 响应

```json
{
  "status": "healthy",
  "version": "1.0.0",
  "start_time": "2026-09-24 10:00:00",
  "uptime_seconds": 3600,
  "uptime_formatted": "1h 0m 0s",
  "total_requests": 1250,
  "success_count": 1180,
  "failed_count": 70,
  "processing_count": 2,
  "processing_ids": ["audio_a1b2c3d4"],
  "queued_count": 0,
  "queued_ids": []
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `status` | string | 服务状态，当前正常时为 `healthy` |
| `version` | string | 服务版本，来自 `config.toml` |
| `start_time` | string | 服务启动时间，格式为 `YYYY-MM-DD HH:MM:SS` |
| `uptime_seconds` | integer | 服务已运行秒数 |
| `uptime_formatted` | string | 人类可读的运行时长 |
| `total_requests` | integer | 已接收的请求数 |
| `success_count` | integer | 业务成功数 |
| `failed_count` | integer | 业务失败数 |
| `processing_count` | integer | 当前正在处理的任务数 |
| `processing_ids` | string[] | 正在处理的任务 ID |
| `queued_count` | integer | 当前排队任务数 |
| `queued_ids` | string[] | 排队任务 ID |

## 4. 音频质检

### 4.1 请求

```http
POST /audio/qc
Content-Type: multipart/form-data
```

表单字段：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `audio_file` | file | 是 | 音频文件。可使用 WAV、MP3、AAC、M4A 等 FFmpeg 能够解码的格式 |
| `task_id` | string | 否 | 调用方自定义任务 ID。未提供时服务端自动生成 |

服务端会按 1 MB 分块读取上传文件，并在读取过程中检查文件大小。空文件会直接返回 `1001`。

### 4.2 curl 示例

不指定任务 ID：

```bash
curl -X POST 'http://127.0.0.1:8090/audio/qc' \
  -F 'audio_file=@./audio.wav'
```

指定任务 ID：

```bash
curl -X POST 'http://127.0.0.1:8090/audio/qc' \
  -F 'audio_file=@./audio.mp3' \
  -F 'task_id=order_20260924_0001'
```

### 4.3 成功响应

```json
{
  "request_id": "audio_a1b2c3d4",
  "status_code": 200,
  "data": {
    "is_silent": false,
    "has_speech": true,
    "speech_ratio": 0.3779,
    "has_clip": true,
    "clip_detail": {
      "clip_count": 2,
      "times_ms": [1250, 8340]
    },
    "clarity": 90.6276,
    "clarity_detail": {
      "snr_db": 14.0525,
      "hf_ratio": 0.062467,
      "spectral_flatness": 0.046862
    },
    "vad": {
      "segments_ms": [[0, 5000], [10000, 15000]],
      "speech_ms": 10000
    }
  }
}
```

顶层字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `request_id` | string | 请求 ID。使用 `task_id` 时为自定义值，否则为“文件名（不含扩展名）+ 8 位随机字符” |
| `status_code` | integer | 业务状态码，成功为 `200` |
| `data` | object | 质检结果。失败时为 `{}` |

`data` 字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `is_silent` | boolean | 是否判定为静音 |
| `has_speech` | boolean | 是否检测到人声。当前实现以合并后人声时长不少于 300 ms 为判定条件 |
| `speech_ratio` | number | 人声时长占音频总时长的比例，范围 `[0, 1]`，保留 4 位小数 |
| `has_clip` | boolean | 是否检测到削波事件 |
| `clip_detail` | object/null | 削波详情。无削波时为 `null` |
| `clarity` | number/null | 清晰度分数，范围 `0-100`。关闭清晰度检测时为 `null` |
| `clarity_detail` | object/null | 清晰度原始指标。关闭清晰度检测时为 `null` |
| `vad` | object | VAD 结果 |

`clip_detail` 字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `clip_count` | integer | 削波事件数量 |
| `times_ms` | integer[] | 每个削波事件的起始时间，单位为毫秒 |

`clarity_detail` 字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `snr_db` | number | 基于 VAD 分段估计的信噪比，单位 dB |
| `hf_ratio` | number | 高频能量占比 |
| `spectral_flatness` | number | 谱平坦度 |

`vad` 字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `segments_ms` | integer[][] | 合并后的语音片段，格式为 `[[开始毫秒, 结束毫秒], ...]` |
| `speech_ms` | integer | 语音片段总时长，单位为毫秒 |

当服务配置 `return_segments=false` 时，`vad.segments_ms` 返回空数组，但 `speech_ms` 仍会返回。配置 `need_clarity=false` 时，`clarity` 和 `clarity_detail` 均为 `null`。

### 4.4 失败响应

```json
{
  "request_id": "audio_a1b2c3d4",
  "status_code": 1002,
  "data": {}
}
```

## 5. 业务状态码

| 状态码 | 含义 | 常见原因 |
|---:|---|---|
| `200` | 成功 | 音频完成全部质检 |
| `1001` | 音频缺失或为空 | 未传 `audio_file`、文件名为空或文件大小为 0 |
| `1002` | 音频时长超出范围 | 音频时长不在配置的最小/最大时长范围内 |
| `1003` | 文件过大 | 上传文件超过 `max_file_size_mb` |
| `2001` | 解码失败 | FFmpeg 无法识别文件或解码失败 |
| `2002` | 重采样失败 | 解码后采样率不是目标 16 kHz |
| `2003` | 音频数据无效 | 音频为空、数组形状异常或包含 NaN/Inf |
| `3001` | VAD 推理失败 | VAD 模型加载或推理异常 |

调用方应始终先检查 HTTP 状态码，再检查 JSON 的 `status_code`。由于当前协议将业务错误也封装为 HTTP 200，不能只依据 HTTP 状态码判断质检是否成功。

## 6. 默认限制与可配置项

默认配置以部署环境中的 `config.toml` 为准。当前仓库示例配置为：

| 配置项 | 默认值 | 说明 |
|---|---:|---|
| `audio_qc.max_file_size_mb` | `300` | 最大上传文件大小 |
| `audio_qc.min_duration_ms` | `10000` | 最小时长 10 秒 |
| `audio_qc.max_duration_ms` | `6600000` | 最长时长 110 分钟 |
| `audio_qc.return_segments` | `true` | 是否返回 VAD 分段 |
| `audio_qc.need_clarity` | `true` | 是否计算清晰度 |
| `audio_qc.merge_gap_ms` | `120` | VAD 片段合并间隔 |
| `audio_qc.silence_dbfs` | `-50.0` | 静音检测阈值 |

部署时如果通过 Docker 挂载外部 `config.toml`，以挂载文件中的值为准。

## 7. Python 调用示例

```python
import requests


url = "http://127.0.0.1:8090/audio/qc"
with open("audio.wav", "rb") as audio:
    response = requests.post(
        url,
        files={"audio_file": ("audio.wav", audio, "audio/wav")},
        data={"task_id": "demo_task_001"},
        timeout=300,
    )

response.raise_for_status()
payload = response.json()

if payload["status_code"] != 200:
    raise RuntimeError(f"音频质检失败: {payload['status_code']}")

result = payload["data"]
print(result["has_speech"], result["speech_ratio"])
```

## 8. 接入建议

1. 使用 `task_id` 关联调用方业务单号，并在调用方保证其唯一性。
2. 客户端超时时间建议不低于 300 秒，长音频和 CPU 推理环境可能需要更长时间。
3. 对 `1001-1003` 做输入校验提示；对 `2001-2003` 做文件格式或音频内容提示；对 `3001` 做服务重试或告警。
4. 不要把 `clip_detail`、`clarity_detail` 或 `vad` 的 `null`/空数组当成接口异常，它们可能是合法业务结果或配置关闭后的结果。
5. 生产环境建议通过网关暴露 HTTPS 地址，并限制上传请求体大小，避免无效大文件占用服务资源。
